## Context

Мотивация в proposal.md (Why). Что важно для подхода:

- `CommentaryStyle` содержит три стиля с инструкциями и резервными репликами; `hostText` выбирает стиль по счётчику реплик и передаёт его инструкцию в системный промпт ведущего.
- Колкость приходит в поле `taunt` ответа игрока, показывается в правой колонке реплик и в `picture.taunt`, вслух не звучит. Системный промпт игрока задаёт «одно короткое сухое английское предложение», язык подставляет `BroadcastLanguage.prompt`.
- `GameMemory` уже хранит данные по ключу маршрут+адрес+модель+цвет и сериализуется в сессию; это готовый образец для хранения персон, но персона не зависит от цвета.
- Переключатель заметки думающего игрока реализован как несохраняемый флаг в `MatchRuntime` и параметр `ProgramTextOverlay`.
- Старт партии проходит через `MatchEngine.start`, где для новой партии вызывается `beginThink`; восстановленная партия и завершённая партия идут другими ветками.

## Goals / Non-Goals

**Goals:**

- Один стиль ведущего без ротации, без следов Хауса в коде и резервных репликах.
- Персона как данные: перечень, инструкция манеры, хранение закрепления; движок и промпт получают персону, не зная её деталей.
- Колкость адресована сопернику и видна на сцене по переключателю.
- Приветствие один раз на партию, без повторов при восстановлении.

**Non-Goals:**

- Голоса персон и ведущего: change `broadcast-voices`.
- Имитация речи реальных людей: персона описывает манеру юмора, промпт запрещает цитаты и представление от чужого имени.
- Выбор персоны пользователем в UI. Закрепление случайное и автоматическое; ручной выбор можно добавить позже без смены спеков.

## Decisions

### 1. `CommentaryStyle` сокращается до одного значения

Удаляются `house` и `carlin` вместе с их резервными репликами; `turn(_:)` всегда возвращает `zadornov`, счётчик `hostCommentaryCount` остаётся только для вариативности резервных реплик. Альтернатива: оставить enum с тремя стилями и фильтр. Отвергнута: мёртвый код и соблазн вернуть ротацию.

### 2. `PlayerPersona` как перечисление с инструкцией

```
public enum PlayerPersona: String, CaseIterable, Codable {
    case carrey, pryor, carlin, chappelle, louisCK, burr, gervais, burnham
    var displayName: String      // имя для сцены и приветствия
    var instruction: String      // манера юмора и подачи для промпта
}
```

Инструкция каждой персоны описывает ритм, интонацию и приёмы (например: Бёрр — рубленые фразы, раздражение на очевидное, без извинений; Бернем — игра слов, самоирония, нарочитая театральность; Джервейс — вежливое унижение с улыбкой), запрещает цитаты, катчфразы и упоминание имени. Промпт игрока добавляет: колкость адресована сопернику по имени стороны, одно предложение, на языке эфира, без оскорблений по признакам и без нецензурной лексики.

### 3. Закрепление и хранение

`PersonaAssignments` — Codable-структура в сессии рядом с `gameMemory`: словарь ключ→персона, где ключ — провайдер и модель (`"Claude|claude-opus-5-5"`), без цвета и без адреса. При запросе персоны для места: есть запись → вернуть; нет → случайная из персон, не встречающихся в словаре; все заняты → случайная из восьми. Запись сохраняется сразу через `onStateChanged`, чтобы персона не менялась между партиями одной серии.

Начальное закрепление для моделей, уже используемых в приложении, разыграно 17 октября 2026 и зашивается как стартовое содержимое словаря при первом запуске новой версии (только для пустого словаря):

| Провайдер | Модель | Персона |
|---|---|---|
| Grok | `grok-4.7` | Луи Си Кей |
| ChatGPT | `chat-latest` | Билл Бёрр |
| Gemini | `gemini-3.8-flash-high` | Джордж Карлин |
| Claude | `claude-opus-5-5` | Рики Джервейс |

Оставшиеся свободными: Ричард Прайор, Бо Бернем, Джим Керри, Дейв Шаппелл. Они достанутся следующим новым моделям случайно.

### 4. Колкость сопернику на сцене

`BroadcastPicture` получает `tauntAuthor: String?` (имя персоны и сторона) рядом с существующим `taunt`. Панель колкости в `ProgramTextOverlay` показывается при флаге `showTaunts` в `MatchRuntime` (несохраняемый, `false` при запуске), по тому же образцу, что и заметка; при включённых обеих панелях колкость располагается над заметкой. Правая колонка реплик не меняется.

### 5. Приветствие

Новый `SpeechKind.intro`. В `start(at:)` для новой партии (`referee.accepted.isEmpty`, `referee.end == nil`, не восстановление) ведущий перед первым `beginThink` произносит приветствие: текст формируется шаблоном на языке эфира без запроса к модели, чтобы старт не ждал сети: приветствие зрителей, «белыми играет <провайдер> <модель> в образе <персона>, чёрными — …». Линия пишется в журнал и архив как остальные реплики. При восстановлении партии приветствие не повторяется.

Альтернатива: просить текст у модели ведущего. Отвергнута для старта: задержка и риск ошибки в первые секунды эфира; стиль Задорнова здесь не нужен, это объявление.

### 6. Таймаут и очередность

Колкость игрока появляется на сцене вместе с ходом, комментарий ведущего идёт после хода как сейчас. Озвучивание колкости отдельным голосом добавит `broadcast-voices`; здесь колкость остаётся текстом, чтобы не менять тайминг эфира в этом change.

## Risks / Trade-offs

- [Модель срывается в оскорбления или имитацию реального человека] → инструкция запрещает цитаты, имена и оскорбления по признакам; `SpokenText.clean` и ограничение длины остаются; резервная колкость пустая, эфир не страдает.
- [Персона «уплывает» при смене адреса провайдера] → ключ без адреса и без цвета, только провайдер+модель.
- [Старые сессии без словаря персон] → поле необязательное, пустой словарь заполняется стартовой таблицей.
- [Приветствие удлиняет старт] → шаблонный текст без сети, длительность одной реплики ведущего.
- [Требование `ai-chess-broadcast` о колкости только голосом ведущего] → здесь не нарушается (колкость текстом), пересматривается в `broadcast-voices`.
