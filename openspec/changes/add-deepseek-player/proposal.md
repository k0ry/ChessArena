## Why

Пользователь хочет сравнивать DeepSeek с другими игроками ChessArena через официальный API. Сейчас DeepSeek отсутствует в выборе провайдера; согласованы модель по умолчанию `deepseek-v4-pro` и thinking с уровнем `high`.

## What Changes

- Добавить DeepSeek для белых, чёрных или обеих сторон с независимым выбором модели. Существующие назначения по умолчанию сохраняются.
- Подключаться напрямую к официальному API с отдельным ключом в Keychain; показывать настройку ключа только при выборе DeepSeek игроком.
- Загружать каталог моделей по запросу пользователя, сохранять ручной ввод ID и не заменять выбранную модель автоматически. По умолчанию использовать `deepseek-v4-pro`.
- Явно включать thinking `high`; запрашивать JSON для хода и обычный текст для послематчевого совета. Извлекать только итоговый ответ, сохраняя изоляцию заметок сторон.
- Сохранять настройки, использовать существующие правила проверки ходов, паузы и повторов, добавив корректную классификацию ошибок DeepSeek.
- Сохранить работу сценического имени, персонажа, озвучки, журнала, памяти серии и архива для нового игрока.

## Capabilities

### New Capabilities

- `ai-players`: дополнительные требования к игроку DeepSeek, его подключению, выбору модели и обработке ответов. Путь уже используется незавершёнными changes, но пока отсутствует в основных `openspec/specs/`; здесь добавляются только требования DeepSeek без копирования требований других провайдеров.

### Modified Capabilities

Нет изменений требований существующих основных спецификаций.

## Impact

Затрагиваются `PlayerConfiguration`, каталог и маршрутизация чатов, `MatchRuntime`, `ControlView`, хранение ключей, обработка ошибок, сетевой журнал и тесты сохранения/матчей. Нужна явная информация о формате ответа в запросе, поскольку ход и послематчевый совет имеют разные форматы. Новая внешняя зависимость — официальный DeepSeek API; дополнительные библиотеки не требуются.

Вне объёма: DeepSeek как ведущий, локальные модели, посредники, вход через веб-аккаунт, автоматическая подмена модели/провайдера и изменение общей политики повторов. Существующие незавершённые changes и локальные правки в общих файлах сохраняются; при реализации требуется сверка с их актуальным состоянием.

Локальные тесты и сборка проверяют интеграцию. Доступ аккаунта, реальные легальные ходы и время ответа подтверждаются отдельной живой проверкой с разрешения пользователя.
