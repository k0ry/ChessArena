## Context

Мотивация и пользовательский объём описаны в [proposal.md](proposal.md), поведение — в [specs/ai-players/spec.md](specs/ai-players/spec.md).

`NeuralProvider` и `ProviderKeys` формируют независимые места игроков. `ArenaChatTransport` уже маршрутизирует HTTP, Anthropic и локальные CLI. Обычный `URLSessionChatTransport` передаёт только `model` и `messages`, а `ChatParser.messageContent` не проверяет причину завершения ответа. `MatchEngine` отдельно запрашивает JSON хода и текстовый послематчевый совет, но пока не обозначает формат в `ChatCall`. Оба запроса уже имеют `effort: high`.

Сетевые/HTTP-ошибки сейчас ставят игру на паузу с экспоненциальным автоповтором 3–60 секунд; нечитаемые ответы расходуют попытку хода. Отменённые и устаревшие результаты защищены поколением запроса. Общая модель ведущего использует тот же enum провайдеров: добавление case без фильтра случайно откроет DeepSeek ведущему.

Условие создания design выполнено: интеграция затрагивает несколько модулей, добавляет внешний API и требует решений по секретам, форматам ответов и совместимости сохранений.

## Goals / Non-Goals

**Goals:**
- Изолировать параметры и разбор DeepSeek от существующих маршрутов.
- Переиспользовать игровые правила, сообщения с заметками, персоны, память и обработку отмены.
- Проверить сетевой контракт на локальных ответах-образцах до обращения к реальному аккаунту.

**Non-Goals:**
- Универсальная переработка всех адаптеров, новый механизм повторов или новый формат хранения ключей.
- Измерение или обещание превосходства Pro над другими моделями по шахматной силе.
- Передача инструментов, сохранение полного рассуждения или отдельный интерфейс настройки reasoning.

## Decisions

### 1. Явный маршрут DeepSeek

Добавить `.deepseek` в `NeuralProvider` и `ChatRoute`, модель `deepseek-v4-pro` и базовый URL `https://api.deepseek.com` в `ModelCatalog`. Место использует `POST /chat/completions`; каталог — `GET /models`. `ProviderKeys` получает отдельное поле с пустым значением по умолчанию, сохраняя совместимость прежних вызовов.

`ArenaChatTransport` делегирует новый маршрут внедряемому `DeepSeekTransport`. Адаптер использует URLSession и существующий `NetworkTrace`; тесты могут подставить локальный сервер. Production-маршрут фиксирован официальным адресом без пользовательского поля endpoint. Перенаправление с авторизацией на другой origin не допускается.

Альтернатива — ветвление по hostname в общем HTTP-адаптере — меньше по объёму, но смешивает параметры сервисов и делает поведение тестового адреса отличным от production. Отдельный маршрут уже соответствует архитектуре Anthropic.

### 2. Формат ответа задаётся назначением запроса

Добавить в `ChatCall` явный формат ответа (например, `text` / `jsonObject`) с обратно совместимым значением `text`. В `playerCall()` назначать `jsonObject`; для послематчевого совета сохранять `text`. Остальные адаптеры не меняют отправляемое тело из-за нового поля. Не определять формат по строкам промпта или уровню `effort`: совет и ход оба используют `high`.

Тело запроса DeepSeek содержит:
- `model`, системное сообщение и существующие `inputMessages`;
- `stream: false`, `thinking: {type: enabled}`, `reasoning_effort: high`;
- начальный технический лимит `max_tokens: 16384`, общий для рассуждения и ответа;
- `response_format: {type: json_object}` только для хода. Существующий промпт уже содержит слово JSON и образец с `move`, `taunt`, `self_notes`.

Не передавать `tools` и параметры генерации, неприменимые к thinking. Лимит 16384 — проектное начальное значение, а не гарантия достаточности для всех позиций; проверить поддержку выбранной моделью и завершение ответа. Превышение не запускает автоматическое увеличение лимита. Сохранить существующие дедлайны игрока и послематчевого обучения.

### 3. Строгая граница итогового ответа

Адаптер разбирает envelope и признак завершения до возврата текста. Для успешного ответа нужны завершённый итоговый текст и отсутствие tool calls; пустое содержимое, неожиданный формат и обрезание по лимиту дают разные причины `.response(.empty/.schema/.truncated)`, даже если начало ответа похоже на готовый JSON. `reasoning_content` не возвращается вызывающему коду и не журналируется. Перед реализацией сверить точные значения признаков завершения с актуальным контрактом Chat Completions.

`ChatParser.moveIntent` и шахматный referee по-прежнему проверяют структуру и легальность хода. Заметки обновляются только после принятого хода. Послематчевый текст проходит существующий `GameMemory.remember`; при ошибке остаётся прежний совет. Это сохраняет раздельные заметки и память сторон даже при одинаковых модели и API-ключе.

Альтернатива — вернуть текст из `choices[0]` без проверки завершения — может принять обрезанный ответ и сохранить неполный совет.

### 4. Ошибки и повторы

Классификатор DeepSeek сопоставляет 401 с аутентификацией, 402 с балансом/квотой, 403 с запретом доступа, 404 с отсутствием модели, 429 с лимитом, 400/422 с параметрами и 5xx со сбоем сервера. Для 402 добавить отдельный безопасный текст о балансе DeepSeek, не показывая сырой body. Не интерпретировать произвольный текст сервиса как пользовательское сообщение. Отмена остаётся `CancellationError`, тайм-аут — `.timeout`, обрыв — `.transport`.

Использовать `MatchEngine.stall`: 401/402, доступ, квота и обрезание требуют ручного продолжения; сеть/сервер/rate limit допускают два повтора с задержками 3 и 6 секунд; неверный формат/нелегальный ход — два корректирующих запроса, затем пауза. Ошибки никогда не создают результат и не меняют счёт. «Продолжить/Повторить» обновляет настройки и сбрасывает только лимит попыток. Адаптер не повторяет запросы и не подменяет модель.

Альтернатива — новая политика остановки для постоянных ошибок — полезна как отдельное изменение для всех провайдеров, но выходит за согласованный объём.

### 5. Каталог и управление

Добавить `DeepSeekConnection` с каталогом, статусом, загрузкой по кнопке и отменой/номером поколения. При смене ключа очищать каталог и игнорировать запоздалый ответ прежнего запроса. Декодировать ID и необязательное отображаемое имя; дополнительные поля API не должны ломать каталог. Сохранять выбранный ID, даже если его нет в новом списке; рядом показывать понятное состояние. Ручной ввод остаётся доступен.

`DeepSeekPanel` содержит SecureField, обновление моделей и безопасный статус. Панель показывается только при DeepSeek среди белых/чёрных. Список ведущего явно исключает DeepSeek, сохраняя действующее исключение Gemini. Блокировать редактирование во время активного запроса; на паузе разрешать исправление подключения/модели. Каталог сам по себе не запускает оплачиваемый пробный ход.

Альтернатива — зашитый список моделей — быстро устаревает; автоматический выбор первого ID неожиданно меняет участника эксперимента.

### 6. Секреты, журнал и сохранение

`MatchRuntime` сохраняет ключ под отдельным аккаунтом `deepseek` в существующем `KeychainSecretStore`. В сессии остаются только enum провайдера и модель. Новые значения enum и поле формата запроса не требуют смены версии сохранённой сессии; `ChatCall` не является сохранённой моделью.

Добавить виды сетевых операций для запроса и каталога DeepSeek и разрешить в безопасном отображении endpoint только `api.deepseek.com`, `/chat/completions`, `/models`. Журнал по-прежнему содержит метаданные без заголовков и тел. Использовать существующее удаление секретов из итогового текста, заметок и памяти.

Персоны назначаются существующим механизмом по паре провайдер/модель, голос определяется персоной. Не добавлять особую персону или голос DeepSeek. Проверить сценическое имя, PGN, журнал, счёт и восстановление партии.

### 7. Проверка и источники

Локальные проверки: точный маршрут/ключ/модель; разница JSON и текста; thinking/effort/лимит; пустой и обрезанный ответ; отдельное рассуждение; ошибки с секретом в body; отмена; каталог и устаревший ответ; независимость сторон; восстановление старой и новой сессии. Затем регрессии существующих адаптеров, матча, памяти, персон и сборка приложения.

Живая проверка — отдельная задача после разрешения на использование ключа: подтвердить принятые легальные ходы DeepSeek белыми и чёрными, независимость двух выбранных моделей (если доступны), сохранение/продолжение, финальный совет и время ответа. Успешный каталог или локальный тест не закрывают эту задачу.

- [Thinking Mode: параметры и отдельное reasoning_content](https://api-docs.deepseek.com/guides/thinking_mode/).
- [JSON Output: формат, лимит и возможность пустого ответа](https://api-docs.deepseek.com/guides/json_mode).

Thinking и JSON заданы независимыми параметрами. Обработка `finish_reason`: `stop` — принять непустой итог; `length` — `.response(.truncated)` с ручной паузой; `tool_calls` — `.response(.schema)`; `content_filter` — существующий `.refused` без автоповтора; `insufficient_system_resource` и `aborted` — `.transport` с действующим повтором, без штрафа за нелегальный ход. Неизвестное или отсутствующее значение — `.response(.schema)`. Доступ аккаунта и качество игры пока не проверены.

## Risks / Trade-offs

- [Thinking расходует время и лимит ответа] → явный бюджет, проверка завершения, существующий дедлайн; реальные задержки измеряются отдельно.
- [JSON mode иногда возвращает пустой ответ] → существующая неудачная попытка без изменения позиции и заметок; отдельный fixture.
- [Общие повторы продолжаются при неверном ключе или нулевом балансе] → безопасная причина и возможность остановить/исправить настройки; общую политику не менять в этом change.
- [Незавершённые changes меняют общие файлы] → перед реализацией сверить рабочее дерево; сохранять текущие правки Claude, Gemini и озвучки, не откатывать их.
- [Несколько changes добавляют `ai-players`] → сохранить общий путь и уникальные названия требований DeepSeek; перед архивированием сверить основную спецификацию и применить только эти добавления.
- [Старая сборка не распознаёт DeepSeek в новой сессии] → документировать ограничение отката и сохранить резервную копию сессии до обновления.

## Migration Plan

1. Реализовать адаптер, каталог и подключение UI поверх текущего дерева; новые значения конфигурации имеют безопасные значения по умолчанию.
2. Проверить чтение старых сессий и round-trip обеих сторон DeepSeek; старые ключи не мигрируют.
3. Выполнить локальные тесты и сборку, затем отдельно согласованную живую проверку.
4. Для возврата к старой сборке сначала выбрать прежних провайдеров в новой сборке и сохранить сессию либо восстановить резервную копию; файл с `DeepSeek` старая версия не декодирует. Запись ключа DeepSeek может оставаться в Keychain.
