## Context

Мотивация в proposal.md (Why). Факты, определяющие подход:

- `SystemVoice` синтезирует через `AVSpeechSynthesizer.write`, проигрывает буферы через `AVAudioEngine` и возвращает `[Int16]` для архива. Голос выбирается только по языку (`AVSpeechSynthesisVoice(language:)`), поэтому звучит системный голос по умолчанию: Milena для русского, Samantha для английского.
- На Mac пользователя 17 октября 2026 установлены для русского только Milena (женский); для английского есть мужские Daniel, Reed, Rocko, Eddy, Fred, Ralph. Мужской русский голос Yuri скачивается пользователем в Системных настройках, приложение этого сделать не может.
- Вход через ChatGPT даёт токен с аудиторией `https://api.openai.com/v1` и используется для Responses API. Документация preview перечисляет ограничения: не поддерживаются аудио-вход, загрузка файлов и транскрипция; про эндпоинт озвучки `/v1/audio/speech` не сказано ничего. Поддержка не подтверждена и проверяется только живым запросом.
- Протокол `Voice` принимает текст и `SpeechKind`; `ScriptedVoice` в тестах возвращает фиктивные сэмплы.
- Колкость игрока после `host-and-player-personas` приходит с персоной; сейчас вслух не звучит.

## Goals / Non-Goals

**Goals:**

- Эфир всегда озвучен: системный режим работает без сети и ключей.
- Один профиль голоса на роль: ведущий и восемь персон; профиль задаёт голос и подачу, а не конкретного человека.
- Режим OpenAI включается только после подтверждённой проверки и всегда имеет запасной системный голос.
- Архив получает звук любого провайдера.

**Non-Goals:**

- Клонирование голосов реальных комиков. Инструкции описывают характер подачи.
- API-ключ OpenAI для озвучки: пользователь выбрал только подписку. Если проверка покажет, что токен подписки озвучку не поддерживает, режим OpenAI не реализуется и остаётся системный.
- Realtime или потоковая озвучка: реплики короткие, достаточно одного запроса на реплику.

## Decisions

### 1. Профиль голоса в протоколе

`Voice.speak(_:kind:)` получает `profile: VoiceProfile`, где `VoiceProfile` — `.host` или `.persona(PlayerPersona)`. Профиль описывает: предпочтительные системные голоса по языку (список идентификаторов в порядке убывания), множитель тона, темп, паузу перед репликой; для OpenAI — имя голоса и текст инструкции подачи. Движок передаёт `.host` для реплик ведущего и `.persona` для колкости.

### 2. Системный режим как обязательный минимум

`SystemVoice` выбирает первый установленный голос из списка профиля (`AVSpeechSynthesisVoice.speechVoices()` по языку и имени), иначе любой мужской голос языка, иначе голос по умолчанию. Ведущий: тон 0,75–0,8 и темп ниже стандартного, паузы между фразами через короткие тире и точки в тексте приветствия; персоны различаются темпом и тоном в пределах, где речь остаётся разборчивой. Если для языка эфира нет ни одного мужского голоса, окно управления показывает подсказку: какой голос скачать (Yuri для русского) и где.

### 3. Проверка озвучки по подписке — первая задача

В `ChatGPTConnection` добавляется проверочный запрос `POST /v1/audio/speech` с токеном входа, коротким текстом и форматом PCM; результат (код ответа, тип ошибки без текста провайдера) показывается в окне управления и записывается в журнал сети. Результат живой проверки фиксируется в этом разделе design.md. Пока проверка не дала 200 и воспроизводимый звук, режим OpenAI в пикере недоступен с пояснением.

Если проверка успешна: `OpenAIVoice` запрашивает озвучку с голосом и инструкцией профиля, формат PCM 16-бит, частота по ответу сервиса; `MatchArchive.appendAudio` получает частоту и ресемплирует при несовпадении с частотой архива; воспроизведение через тот же `AVAudioEngine`. Любая ошибка — переход на `SystemVoice` для этой реплики без прерывания эфира.

### 4. Очерёдность звука

После принятого хода: комментарий ведущего, затем колкость игрока голосом персоны, затем следующий запрос хода. Колкость пропускается, если пустая или если партия завершилась ходом (итог ведущего важнее). Реплики ожидания ведущего не прерывают колкость. Общая длительность звука на ход растёт на одну короткую реплику; тайм-аут ведущего не меняется.

### 5. Переключатель провайдера

`VoiceProviderChoice { system, openAIChatGPT }` в `MatchRuntime`, сохраняется в сессии; по умолчанию `system`. Проверка тона использует выбранный провайдер и профиль ведущего, чтобы услышать голос до эфира.

## Risks / Trade-offs

- [Токен подписки не поддерживает озвучку] → ожидаемый исход; системный режим реализуется первым и остаётся единственным, проверка остаётся в приложении как диагностика.
- [Мужской русский голос не установлен] → подсказка о скачивании; до этого русский эфир звучит доступным голосом с пониженным тоном.
- [Различие персон системными голосами слабое] → различие темпом, тоном и паузами; это ограничение режима, не ошибка.
- [Задержка OpenAI удлиняет паузы] → колкость запрашивается параллельно с комментарием ведущего и проигрывается после него.
- [Частота дискретизации OpenAI отличается от архива] → ресемплирование в `appendAudio`.
- [Условия использования токена подписки для сторонних эндпоинтов] → приложение использует только документированный вход и один проверочный запрос; при отказе сервиса не обходит ограничение.
