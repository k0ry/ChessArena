## Context

Мотивация и объём — в [proposal.md](proposal.md). Поведение — в [specs/ai-players/spec.md](specs/ai-players/spec.md).

В текущем коде `NeuralProvider` содержит Grok и ChatGPT. `PlayerConfiguration` выбирает URL, модель и ключ выражениями с двумя ветками. `MatchRuntime` создаёт игроков и отдельного ведущего Grok. `ArenaChatTransport` направляет OpenAI-запросы в авторизованную ChatGPT-сессию, остальные — в HTTP Chat Completions. Судья не зависит от провайдера. Существующий интеграционный тест охватывает четыре пары провайдеров.

Gemini через подписку требует нового способа выполнения запроса: локальный процесс официального Antigravity CLI. Добавление третьего URL к существующему HTTP-клиенту эту задачу не решает. Условие включения design.md выполнено: появляется внешняя зависимость и меняются интерфейс, маршрутизация и жизненный цикл запросов.

## Goals / Non-Goals

**Goals:**
- Сохранить общий интерфейс получения хода и изолировать особенности CLI в отдельном адаптере.
- Держать авторизацию внутри официального клиента Google, а обработку ошибок и отмену — внутри приложения.
- Сделать результат воспроизводимым: точная модель, самостоятельный контекст запроса, ограниченный ответ и отсутствие инструментов.

**Non-Goals:**
- Собственный OAuth-клиент к внутренним endpoint Google, чтение чужих токенов, автоматизация веб-чата Gemini.
- API-ключ Gemini, Vertex AI, Gemini Enterprise и старый Gemini CLI.
- Gemini в роли ведущего, смена провайдера посреди партии, новые шахматные правила.
- Автоматическая установка, обновление CLI или изменение глобальных настроек Antigravity без отдельного действия пользователя.

## Decisions

### 1. Официальный CLI с проверкой совместимости

Использовать установленный `agy` и документированный headless-режим. Начальный поиск: сохранённый абсолютный путь и стандартные места установки; для приложения из Finder нельзя полагаться только на shell PATH. Пользователь может выбрать исполняемый файл. Проверять версию и поддерживаемые параметры до включения подключения; несовместимость показывать как состояние зависимости.

Документация на 10 октября 2026 года подтверждает:
- [Gemini CLI больше не обслуживает потребительские подписки с 18 июня 2026 года](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals).
- [Antigravity CLI поддерживает вход Google через браузер и хранение сессии в системном хранилище](https://www.antigravity.google/docs/cli/install/).
- [Headless-режим поддерживает кэшированную сессию, JSON-вывод, JSON schema, выбор модели и таймаут](https://www.antigravity.google/docs/cli/headless/).
- [Квоты Antigravity зависят от Google AI Pro/Ultra; перерасход AI credits регулируется отдельной настройкой](https://www.antigravity.google/docs/plans).

Альтернатива с обычным Gemini API не обеспечивает выбранный пользователем способ доступа через подписку. Документированный [Antigravity SDK](https://www.antigravity.google/docs/sdk/overview/) в quickstart использует API-ключ, поэтому не является основанием для обещания подписочного доступа.

### 2. Локальная реализация и проверка готовности

По прямому запросу пользователя от 11 октября 2026 года реализуется только локальный CLI. Серверный эксперимент исключён из архитектуры приложения: без SSH, HTTP bridge и переноса сессий. Реализация и автоматические тесты продолжаются независимо от доступности конкретного аккаунта; неподтверждённый живой доступ не обозначается как готовность.

Перед стартом игры пользователь проверяет выбранную модель тестовым легальным ходом. Каталог и OAuth отдельно не являются доказательством возможности генерации. Тип платного плана остаётся внешним свойством аккаунта; приложение не обещает наличие подписки, не подставляет API-ключ и перед каждым ходом проверяет отключение дополнительных кредитов.

### 3. Раздельные маршруты и учётные данные

Заменить двоичные допущения в конфигурации на исчерпывающий выбор провайдера. Отделить описание игрока от способа доступа: HTTP с API-ключом, сессия ChatGPT, подписочная сессия Gemini через CLI. Не кодировать Gemini фиктивным HTTP URL и не передавать ему ключи xAI/OpenAI.

Сохранить общий контракт асинхронного получения текста для движка. Маршрутизатор выбирает адаптер по явному провайдеру/способу подключения. Ведущий сохраняет уже реализованный выбор Grok/ChatGPT независимо от белых; Gemini добавляется только игрокам. Старт и продолжение используют один путь валидации и построения настроек стороны.

### 4. Подключение и выбор модели

Состояния панели: CLI отсутствует, версия несовместима, требуется вход, выполняется вход, готово, доступ/квота недоступны. Успешное завершение браузерного этапа само по себе не означает готовность запросов: подтвердить сессию официальным механизмом CLI. Если требуется интерактивный терминал, открыть штатный сценарий клиента и вернуться к проверке в ChessArena. Приложение не перехватывает пароль, код или токен.

Список распознаваемых Gemini-моделей получать через документированную команду `agy models` для проверенной версии. Для каждой стороны хранить отдельный идентификатор. Исключить автоматический выбор другой модели при ошибке. Если список нельзя прочитать, показать ошибку загрузки; не подменять её пустым подтверждённым каталогом. Наличие модели не подтверждает квоту аккаунта.

### 5. Один ограниченный процесс на запрос хода

Запускать CLI через `Process` с массивом аргументов и pipes, без shell-интерполяции. Использовать новый контекст на каждый ход: приложение уже передаёт полную принятую историю и FEN, поэтому продолжение CLI-разговора не требуется. Это исключает смешивание контекстов двух игроков.

Использовать точную модель и JSON-вывод CLI. Поля `move` и `taunt` проверяются в приложении. Режим `--json-schema` исключён после живой проверки 1.3.3: он вернул повторяющийся частичный ответ по тайм-ауту; без него завершённый ответ получен за 4.95 с. Выделять итоговый ответ из служебной оболочки; промежуточные события и рассуждения не публиковать. Предпочесть stdin для текста запроса, если это подтверждено для выбранного режима; не изобретать сочетания параметров до проверки CLI.

Запускать в отдельном рабочем каталоге. Исключить загрузку проектных инструкций, расширений, MCP, hooks и пользовательских агентов; штатной политикой отключить инструменты. Один запрет в prompt не считается изоляцией. Не использовать пропуск разрешений. Проверка этого режима входит в первый этап; если отключение подтвердить нельзя, запросы игры не разрешать.

Читать stdout/stderr одновременно, с ограничением размера буферов. По таймауту, отмене или закрытию приложения завершать принадлежащий запросу процесс и его дочерние процессы; дождаться завершения и закрыть pipes. Проверять поколение запроса перед передачей результата судье. Таймаут адаптера должен согласовываться с таймаутом CLI и не блокировать MainActor.

### 6. Ошибки, квота и конфиденциальность

Отдельно распознавать ошибки CLI/транспорта и успешный ответ модели. Повреждённая оболочка, отсутствие результата, ненулевой exit code, `WAITING` или отказ инструмента приводят к паузе. Доставленный ответ с нелегальным/неразбираемым ходом остаётся в существующем цикле судьи. При продолжении — та же позиция и актуальная модель стороны.

Проверять режим подключения и перерасхода до отправки хода через поддерживаемые механизмы CLI. Не менять глобальный выбор пользователя молча. Если автоматические AI credits включены и нет подтверждённого переопределения для запроса, показать требуемую настройку и не запускать генерацию. Не наследовать альтернативный API-режим по случайным переменным окружения. На исчерпании квоты — пауза без переключения модели или оплаты.

В UI и журналы передавать только безопасные категории: нужна установка/совместимая версия, нужен вход, модель недоступна, квота, таймаут, ошибка выполнения. Не сохранять сырой stderr, OAuth-ссылки и диагностические дампы. Успешную реплику модели обрабатывать существующим путём игры.

## Risks / Trade-offs

- [Документация не доказывает доступ конкретного аккаунта] → Проверить подписку живым запросом и записать отдельное свидетельство; фиктивные ответы этого не заменяют.
- [CLI меняет формат вывода или параметры] → Зафиксировать проверенную версию и fixtures, явно отклонять неподдерживаемые варианты.
- [Запуск процесса добавляет задержку к каждому ходу] → Измерить её на проверке; сохранять текущую анимацию ожидания и ограниченный таймаут.
- [Глобальные настройки CLI включают инструменты или дополнительную оплату] → Проверять эффективный режим, использовать подтверждённую изоляцию; при невозможности остановить подключение.
- [Два change используют `ai-players`] → Сверить требования перед архивацией, не потерять базовые сценарии `ai-chess-broadcast`.
- [Ведущий по-прежнему требует xAI] → Явно указать это в управлении и инструкции даже для Gemini против Gemini.

## Migration Plan

1. На этапе реализации проверить официальный CLI и реальную подписку, затем интегрировать адаптер и интерфейс.
2. Сохранить прежние настройки Grok/ChatGPT и их значения по умолчанию. Добавить только параметры подключения Gemini, без копирования его секретов.
3. Выполнить автоматические проверки и живой прогон, собрать приложение и обновить пользовательскую инструкцию.
4. Для отката вернуть сборку без Gemini; сохранённые партии и существующие ключи сохраняются. Установка CLI и его Google-сессия принадлежат пользователю и не удаляются приложением при откате.
